# 作品简介：EvidenceLoop（循证实训 Agent）

> 报名/表单短句见 [SUBMISSION_GUIDE.md](./SUBMISSION_GUIDE.md)。本文可作附件「作品简介」正文。

## 一句话

EvidenceLoop 用**可复现证据**驱动多学科实训闭环：只证据打分，大模型只辅导不改分，练习与测评分流，教师终裁与提示可审计。

## 项目名称说明

- **正式名**：EvidenceLoop · 循证实训 Agent  
- **是否改名**：**否。** 初赛至今品牌、仓库与 UI 一致；能力从编程扩展到多学科，但「循证 + 闭环」定位未变。详见提交指南 §0。

## 目标用户

1. **学员**：课堂/机房完成练习与测评，需要即时、可解释、可复现的反馈，以及错题重练与复习节奏。  
2. **教师/助教**：布置作业、站内提示、主观题终裁、班级学情；保留成绩权威，拒绝暗箱改分。  
3. **课程/产品团队（间接）**：复用 Agent 模板、题型 Runner、知识点 DAG 与合规边界说明。

## 场景痛点

- 自动批改只给对错，缺少「为什么错、下一步练什么」。  
- 大模型直接讲评易幻觉，且容易越权改分。  
- 练习刷题与正式掌握混计，学情不可信。  
- 教师缺少与客观分并列的可审计终裁，以及「消息不是分」的沟通渠道。  
- 传统 OJ 有测试，但缺少双模、辅导隔离、教师工作流与多学科题型编排。

## 任务闭环（可演示）

1. 教师布置（手选 / 知识点 / 薄弱点）或学生进入「今日该练」  
2. 学生在**练习态**或**测评态**作答（D1 双模）  
3. 题型 Runner 产出可复现 Evidence，量规归约分数（LLM 不参与改分）  
4. 练习态可 AI 辅导（与打分路径隔离）；测评态关闭辅导门禁  
5. 错题本重练（仍练习态）+ FSRS 复习调度  
6. 教师站内提示（消息不是分）与主观题终裁（annotation 不折叠 score）  
7. 班级学情：中位分尊重终裁门与待裁排除  

**编程强 demo（初赛延续）**：缺陷提交约 80 分（证据未全过）→ 应用修复 → 100 分，教师学情同步。

## Demo 价值证明

| 证明点 | 现场信号 |
|--------|----------|
| 证据打分 | 提交后可见证据条与维度，非一句模型分 |
| LLM 不改分 | 练习态求助前后 score 不变 |
| 双模 | 徽章区分练习/测评；重练回练习态 |
| 提示非分 | 教师发提示 → 学生收件箱；成绩区无变化 |
| 终裁不折叠 | teacherAnnotation 与客观分并列 |
| 工程可复现 | `npm run check`；E2E demo loops 16/16 |

## 差异化

| 维度 | 常见 AI 助教 | 传统 OJ | EvidenceLoop |
| --- | --- | --- | --- |
| 评分 | 模型主观 | 测试客观 | 多题型证据 + 量规，客观可复现 |
| 解释 | 易幻觉 | 通常缺失 | 受证据约束；辅导可 LLM |
| 练习/考试 | 常混计 | 偏考试 | D1 硬分流 |
| 教师 | 旁观或灌分 | 看分 | 终裁可审计、提示非分、学情门禁 |
| 合规 | 模糊 | 窄 | 审计链、隔离运行、PII/egress 边界写清 |
| 学科 | 聊天通用 | 偏代码 | 7 题型 × 9 学科 KP |

## 技术要点（对外）

- **Agent 编排**：读取任务 → 受限验证 → 量规评分 → 知识匹配 → 反馈；评分步不靠聊天记忆改分。  
- **Runner**：choice / fill_blank / numeric / expression / chem_equation / code / essay 等注册制扩展。  
- **执行**：代码题默认可本地子进程 Demo；可启用 Docker 无网容器池。  
- **记忆与自适应**：掌握度与 FSRS 复习与评分闭环隔离（架构测试守护）。  
- **多模态（可选）**：语音讲解与 DOM 高亮，feature flag 可关，不改分。  
- **栈**：React 19、Vite、Node、TypeScript、SQLite、Zod；Apache-2.0。

## 合规边界（必须写进材料）

- Demo 匿名样例与演示角色；**非**生产多租户。  
- 模型不改分；教师终裁不批量灌分。  
- 学生 PII 设计上不出境；审计可查询。  
- 公开生产仍需真身份、密钥托管、容量与教务对接——**不在本次 Demo 宣称范围**。
