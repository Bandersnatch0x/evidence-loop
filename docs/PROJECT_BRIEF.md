# 作品简介：EvidenceLoop（循证实训 Agent）

## 一句话

EvidenceLoop 用“可验证证据”驱动编程实训闭环：提交代码后自动运行、评分、诊断薄弱知识点，并生成下一轮修复任务。

## 目标用户

1. 编程初学者：需要即时、可解释、可复现的作业反馈。
2. 实训教师/助教：需要班级学情、薄弱点队列和干预建议，而不是泛化聊天答复。
3. 课程产品团队：需要可复用的 Agent 模板，而不是单次演示脚本。

## 场景痛点

- 自动批改只给对错，缺少“为什么错、下一题修什么”。
- 大模型直接讲评容易幻觉，也容易越权改分。
- 教师无法快速看到班级层面的证据队列和关注对象。
- 传统 OJ 有测试，但缺少 Agent 式任务编排与知识诊断。

## 任务闭环

1. 学习者提交 Python 函数实现
2. 受限运行器执行公开/隐藏测试与静态检查
3. 量规把证据映射为维度分与总分
4. 知识库把失败证据映射为诊断
5. 生成下一轮干预任务
6. 学习者修复并再次提交
7. 历史与班级学情更新

## Demo 价值证明

- 缺陷版：80 分，7/8 证据通过，诊断“空序列边界未处理”
- 修复版：100 分，8/8 证据通过，相对上一轮 +20
- 教师视图同步显示演示学员掌握状态

## 差异化

| 维度 | 常见 AI 助教 | 传统 OJ | EvidenceLoop |
| --- | --- | --- | --- |
| 评分 | 模型主观 | 测试客观 | 测试+量规客观 |
| 解释 | 易幻觉 | 通常缺失 | 受证据约束 |
| 下一动作 | 泛化建议 | 无 | 生成可验证干预任务 |
| 教师角色 | 旁观 | 看分 | 看证据与干预队列 |
| 合规边界 | 模糊 | 明确但窄 | 明确：模型不改分 |
