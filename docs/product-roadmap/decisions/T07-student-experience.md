## ✅ 已解决（resolution）

**状态**：closed。补充刚需1（错题本 + 场次模型）落地。类型偏 prototype，此处定交互模型，实建时用 /prototype 打磨 UI。

### 练习"场次"模型（Session）
- 引入 **PracticeSession** 概念（挂在 Attempt 之上的分组）：一次练习 = 一组 Attempt。
- **两种入口**：
  - **自由练**：一题一交一反馈（现有交互），mode=practice，AI 辅导全开。
  - **成套测评**：多题打包 + 计时 + 统一交卷后看结果，mode=assessment，辅导关闭（对齐 D1）。
- Session 记 `mode/termId/teachingUnitId`，其下 Attempt 继承。

### 错题本（补充刚需1）
- **自动归集**：任一 Attempt 判错（evidence 有 failed）→ 自动进该生错题本，按学科/知识点分组。
- **重刷**：错题本里可重练；重练是新 Attempt（practice 态），旧错题记录保留（不覆盖，可追溯进步）。
- **销号**：同一题连续 N 次（默认 2）测评态判对 → 标记"已掌握"移出活跃错题本（进历史）。

### 练习态/测评态入口区分（D1，用户可见）
- UI 明确标识当前模式：练习态显示"练习中·辅导开启"，测评态显示"测评中·独立完成"。
- 测评态入口需老师布置或学生主动选"模拟测评"，不能随意切——防止刷分绕过。

### 提示/求助中间态（与 T05 苏格拉底联动）
- 练习态每题有"求助"按钮 → 触发 T05 苏格拉底引导（一次一问，不直接给答案）。
- 连续 3 次低努力索取 → 按 Khanmigo 防套话机制拒绝继续放提示（TR2）。

### 移动端（从 fog 拉入决策）
- **裁决：响应式 Web 优先，不做原生 App**。"自主刷题"确有手机场景，但原生 App 是重投入且出界产品原型范围。现有前端已有 mobile 响应式痕迹，沿此路做到"手机可用"即可。原生 App 留 Out of scope。
